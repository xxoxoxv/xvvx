# أهداف التعافي من الكوارث

## الأهداف

| المؤشر | الهدف | الوصف |
|--------|------|------|
| RPO | 0 دقيقة | فقدان بيانات صفري (Event Sourcing + نسخ متزامنة) |
| RTO (خدمة) | < 15 دقيقة | استعادة الخدمة الكاملة |
| RTO (نموذج) | < 5 دقائق | استرجاع ألفا السابقة |
| RTO (بيانات) | < 60 دقيقة | استرجاع Event Store من الأرشيف |

## سيناريوهات الكوارث

| السيناريو | الاستجابة | RTO متوقع |
|---------|---------|-----------|
| فشل عقدة | Kubernetes auto-heal | < 2 دقيقة |
| فشل منطقة سحابية | تجاوز فشل لمنطقة بديلة | < 15 دقيقة |
| فساد بيانات | استرجاع من Event Store + Object Store | < 60 دقيقة |
| نموذج ملوث | استرجاع ألفا السابقة + حذف النسخة الملوثة | < 5 دقائق |
| هجوم أمني | Kill Switch + عزل + استرجاع | < 30 دقيقة |
| كارثة طبيعية | استرجاع من نسخة جغرافية بعيدة | < 4 ساعات |
| فقدان فريق بشري | توثيق + Runbooks + لجنة بديلة | < 7 أيام |

## اختبارات إلزامية

| الاختبار | التكرار | الوصف |
|---------|--------|------|
| استرجاع Event Store | شهري | استرجاع آخر 30 يوم من الأرشيف |
| استرجاع نموذج | ربع سنوي | استرجاع ألفا من نسختين سابقتين |
| تجاوز الفشل | ربع سنوي | محاكاة فشل منطقة كاملة |
| Chaos Testing | شهري | إيقاف عقد عشوائية + حقن أخطاء |
| استرجاع كامل | سنوي | محاكاة كارثة كاملة من الصفر |
