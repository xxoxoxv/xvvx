# سياسة الإصدار — Versioning Policy

> **المجال:** docs/maturity
> **المرحلة:** P9 — النضج والفصل المستقبلي
> **الحالة:** سياسة (Policy)
> **تاريخ الإنشاء:** 2026-08-15

---

## 1. الهدف
تعريف كيفية إصدار وترقيم إصدارات الدولة وأجزائها، لضمان توافق الإصدارات والترقية الآمنة.

## 2. نمط الترقيم
Semantic Versioning: `MAJOR.MINOR.PATCH`

- **MAJOR** — تغييرات مدمرة في العقود/المخططات.
- **MINOR** — إضافات متوافقة عكسيًا (ميزات/مخططات جديدة).
- **PATCH** — إصلاحات أخطاء دون تغيير العقود.

## 3. دورة الإصدار
| النوع | الدورية | مثال |
|---|---|---|
| إصدارات رئيسية | ربع سنوي | `1.0.0` → `2.0.0` |
| إصدارات فرعية | شهري | `1.0.0` → `1.1.0` |
| تصحيحات | عند الحاجة | `1.0.0` → `1.0.1` |

## 4. قواعد التوافق
1. كل تغيير في JSON Schema (`additionalProperties`, `required`) يتطلب ترقية MINOR على الأقل.
2. حذف حقل أو تغيير نوعه = MAJOR.
3. إضافة حقل اختياري = MINOR.
4. التوافق العكسي مضمون ضمن نفس MAJOR.

## 5. سجل الإصدارات
يُحفظ سجل التغييرات (CHANGELOG) في `docs/implementation/PROGRESS_LOG.md` لكل إصدار، مع ربط كل إصدار بالمرحلة (P0–P9).
