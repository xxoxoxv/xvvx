## 1. التعريف

```
DONE = Capability Proven
```

«تم» ليست حالة ملف. «تم» حالة **قدرة مُثبَتة**.

---

## 2. المعايير الستة عشر للإقفال

لا تُعتبر مهمة منتهية إلا إذا تحققت **كل** هذه البنود:

| # | المعيار | كيف يُثبَت |
|---|---|---|
| 1 | تنفيذ حقيقي | كود يعمل، لا stub ولا وثيقة |
| 2 | مصدر حقيقة حقيقي | قاعدة بيانات/API فعلي، لا قوائم ثابتة ولا `InMemory` |
| 3 | اختبارات unit | تغطي المنطق الداخلي |
| 4 | اختبارات integration | تعبر حدود المكوّنات فعليًا |
| 5 | اختبارات failure | انقطاع قاعدة بيانات، timeout، رد مشوّه |
| 6 | اختبارات security | صلاحيات، تسلل، تصعيد امتياز |
| 7 | observability | سجلات + مقاييس + أحداث |
| 8 | persistence | الحالة تنجو من إعادة التشغيل |
| 9 | recovery | استعادة مُختبَرة، لا موصوفة |
| 10 | authorization | كل فعل يمر عبر سلطة معرّفة |
| 11 | audit trail | كل قرار مسجّل بلا إمكانية عبث |
| 12 | documentation | موثّق ومطابق للواقع |
| 13 | migration strategy | كيف ننتقل من الحالة السابقة |
| 14 | production configuration | إعداد إنتاجي بلا أسرار افتراضية |
| 15 | CI verification | بوابة آلية تمنع التراجع |
| 16 | تشغيل فعلي مُثبت | شُغِّل النظام وحُفظ الدليل |

**سقوط أي بند = المهمة ليست DONE.**

---

## 3. نظام الحالات المعتمد

| الحالة | المعنى | شرط الانتقال |
|---|---|---|
| `DESIGNED` | فكرة موصوفة | يوجد وصف معماري |
| `SPECIFIED` | عقد مكتوب | مخطط/واجهة/schema محددة |
| `IMPLEMENTED` | كود موجود ويعمل | يمرّ import ويُنفَّذ |
| `UNIT_TESTED` | منطق مغطّى | اختبارات وحدة تمر |
| `INTEGRATED` | مربوط بالنظام | يعبر حدود المكوّنات على مصدر حقيقي |
| `SECURITY_TESTED` | مؤمَّن | لا أسرار ثابتة، صلاحيات مختبَرة |
| `LOAD_TESTED` | يتحمل | اختبار حِمل موثّق |
| `DEPLOYED` | منشور | يعمل في بيئة نشر حقيقية |
| `OBSERVED` | مُراقَب | سجلات ومقاييس وتنبيهات حية |
| `PROVEN` | **مُثبَت** | كل ما سبق + المعايير الستة عشر |

الحالات القديمة `TODO / DOING / DONE` **ملغاة** في هذا المستودع.

## 5. الاختبار النهائي للدولة — GRAND STATE TEST

المشروع لا يُعلن ناجحًا لأن CI أخضر. يُعلن ناجحًا عندما يمر هذا السيناريو كاملًا من طرف إلى طرف على مصادر حقيقة حقيقية:

```
إصدار مرسوم من الملك
        ↓ التحقق الدستوري
        ↓ التحقق من السلطة
        ↓ التفسير الفدرالي
        ↓ تحليل أثر الولايات
        ↓ التنفيذ المؤسسي
        ↓ تنفيذ الوكلاء للمهام
        ↓ استدعاء الأدوات داخل عزل
        ↓ إصدار الأحداث
        ↓ تسجيل التدقيق
        ↓ تحديث الذاكرة
        ↓ تحديث الخزانة عند اللزوم
        ↓ التحقق من النتيجة
        ↓ تقرير للملك والحكومة
```

يضاف إليه مسار الفشل: مراقبة وكيل ← اكتشاف خطأ ← عزل الوكيل ← استعادة النظام ← استكمال المهمة ← تقرير.

**إذا فشل هذا الاختبار، الدولة ليست مكتملة — مهما بلغ عدد الملفات.**

---

## 6. تعريف 100%

«100%» لا تعني توقف التطور. تعني:

> كل قدرة أساسية موجودة، ومترابطة، وقابلة للتشغيل، ومختبَرة، ومؤمَّنة، وقابلة للمراقبة، وقابلة للاستعادة.

بعدها يبدأ `Evolution`، وليس `Completion`.
